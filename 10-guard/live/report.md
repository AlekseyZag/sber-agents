# Отчет по ДЗ-10: Безопасность агентных систем

## Реализованные механизмы безопасности

### 1. Маскирование чувствительных данных (PII)

- ✅ **PIIMiddleware** для маскирования номеров кредитных карт
  - Тип PII: `credit_card`
  - Стратегия: `mask` (оставляет последние 4 цифры)
  - Применение: только к выходным сообщениям агента (`apply_to_output=True`)
  
- ✅ **Дополнительная ручная маскировка** для результатов инструментов
  - Функция `mask_card_number_in_text()` для маскирования номеров карт в результатах `ToolMessage`
  - Причина: `PIIMiddleware` не применяется к результатам инструментов, только к ответам агента
  - Поддерживает форматы: `XXXX-XXXX-XXXX-XXXX`, `XXXXXXXXXXXXXXXX`, `XXXX XXXX XXXX XXXX`
  - Пример: `5105-1051-0510-5100` → `****-****-****-5100`

### 2. Лимиты на вызовы

- ✅ **ModelCallLimitMiddleware**: лимит **2** вызовов модели за один запуск
  - Защита от бесконечных циклов рассуждения
  - Контроль расходов на API-вызовы
  
- ✅ **ToolCallLimitMiddleware**: лимит **2** вызовов инструментов за один запуск
  - Защита от избыточных вызовов инструментов
  - Предотвращение зависаний агента

### 3. Human-in-the-Loop

- ✅ Инструменты требующие подтверждения:
  - `open_credit_card` - открытие кредитных/дебетовых карт
  - `open_deposit` - открытие вкладов
  
- ✅ Реализация:
  - Кнопки подтверждения: "✅ Да" / "❌ Нет"
  - Параметры операции отображаются на русском языке
  - Поддержка решений: `approve` и `reject`
  - Агент останавливается до получения подтверждения пользователя

### 4. Дополнительные фильтры

- ✅ **Валидация сообщений** перед передачей в агент
  - Фильтрация сообщений с `content=None`
  - Предотвращение ошибок типа `'NoneType' object has no attribute 'strip'`
  
- ✅ **Обработка пустых ответов** агента
  - Fallback на результаты инструментов, если агент не сформировал ответ
  - Использование результатов `open_credit_card` напрямую, если ответ пустой

## Сложности и решения

### Проблема 1: PIIMiddleware не маскирует результаты инструментов
**Проблема:** `PIIMiddleware` применяется только к выходным сообщениям агента (`AIMessage`), но не к результатам инструментов (`ToolMessage`). Номер карты из `open_credit_card` попадал в ответ пользователю без маскировки.

**Решение:** Добавлена функция `mask_card_number_in_text()` и применена к результатам `open_credit_card` перед использованием в ответе. Это создает **двухслойную защиту**: PIIMiddleware для ответов агента + ручная маскировка для результатов инструментов.

### Проблема 2: Ошибка при обработке Command объекта
**Проблема:** При вызове `agent_resume` передается объект `Command`, а не словарь. Проверка `"messages" in inputs` вызывала ошибку `"argument of type 'Command' is not iterable"`.

**Решение:** Добавлена проверка типа `isinstance(inputs, dict)` перед валидацией сообщений. Для `Command` объектов валидация пропускается.

### Проблема 3: Ошибки парсинга Markdown в Telegram
**Проблема:** Telegram API выдавал ошибку `"Can't find end of the entity starting at byte offset"` при использовании Markdown форматирования в сообщениях с параметрами операций.

**Решение:** Убрано Markdown форматирование из сообщений подтверждения операций. Сообщения отправляются как обычный текст, что исключает ошибки парсинга и работает с любыми значениями параметров.

### Проблема 4: Пустые ответы от агента
**Проблема:** Иногда агент возвращал пустой `AIMessage` без content и tool_calls, особенно после подтверждения операций.

**Решение:** Добавлена обработка пустых ответов с fallback на результаты инструментов. Если агент вызвал инструмент, но не сформировал ответ, используется результат инструмента напрямую.

### Проблема 5: Зависимость jq на Windows
**Проблема:** Библиотека `jq` требовала компиляции на Windows и не поддерживала Python 3.14.

**Решение:** Удалена зависимость от `jq`, заменена на стандартный парсинг JSON через `json.load()`. Это упростило код и улучшило совместимость.

## Инсайты

1. **Многослойная защита критична**: Один механизм безопасности (PIIMiddleware) может не покрыть все случаи. Необходима дополнительная ручная маскировка для результатов инструментов, которые обходят стандартные middleware.

2. **Human-in-the-Loop обязателен для финансовых операций**: Подтверждение пользователя перед критичными операциями (открытие карт, вкладов) не только повышает безопасность, но и улучшает UX, давая пользователю контроль над действиями агента.

3. **Валидация на всех уровнях**: Валидация сообщений нужна не только на входе, но и при обработке истории диалога, чтобы избежать ошибок с `None` значениями и некорректными типами данных.

4. **Простота лучше сложности**: Убрать Markdown форматирование оказалось проще и надежнее, чем пытаться правильно экранировать все специальные символы. Обычный текст работает стабильнее.
