# Отчет об экспериментах RAG системы

## 📋 Общая информация

**Дата проведения экспериментов:** 23 ноября 2024  
**Датасет:** `06-rag-qa-dataset`  
**Количество примеров:** 6  
**LLM провайдер:** Ollama (`llama3.1:8b`)  
**Embeddings провайдер:** HuggingFace (`intfloat/multilingual-e5-base`)

## 🎯 Цель экспериментов

Сравнить эффективность трех режимов retrieval:
1. **Semantic** - векторный поиск по смыслу
2. **Hybrid** - комбинация Semantic + BM25
3. **Hybrid + Reranker** - Hybrid + Cross-encoder переранжирование

Определить оптимальную конфигурацию для задачи ответов на вопросы по документам Сбербанка.

---

## 🔧 Конфигурации экспериментов

### Эксперимент 1: Semantic Retrieval

**Конфигурация:**
```bash
RETRIEVAL_MODE=semantic
SEMANTIC_RETRIEVER_K=10

# LLM
LLM_PROVIDER=ollama
OLLAMA_MODEL=llama3.1:8b
OLLAMA_MODEL_QUERY_TRANSFORM=llama3.1:8b

# Embeddings
EMBEDDING_PROVIDER=huggingface
HUGGINGFACE_EMBEDDING_MODEL=intfloat/multilingual-e5-base
HUGGINGFACE_DEVICE=cpu
```

**Описание:**
- Использует только векторный поиск по смыслу
- Базовый подход для сравнения
- Быстрый, но может пропускать точные термины

---

### Эксперимент 2: Hybrid Retrieval (Semantic + BM25)

**Конфигурация:**
```bash
RETRIEVAL_MODE=hybrid
SEMANTIC_RETRIEVER_K=10
BM25_RETRIEVER_K=10
ENSEMBLE_SEMANTIC_WEIGHT=0.5
ENSEMBLE_BM25_WEIGHT=0.5

# LLM
LLM_PROVIDER=ollama
OLLAMA_MODEL=llama3.1:8b
OLLAMA_MODEL_QUERY_TRANSFORM=llama3.1:8b

# Embeddings
EMBEDDING_PROVIDER=huggingface
HUGGINGFACE_EMBEDDING_MODEL=intfloat/multilingual-e5-base
HUGGINGFACE_DEVICE=cpu
```

**Описание:**
- Комбинация векторного поиска (semantic) и лексического поиска (BM25)
- Semantic находит документы по смыслу
- BM25 находит точные совпадения терминов
- RRF (Reciprocal Rank Fusion) объединяет результаты с весами 50/50

---

### Эксперимент 3: Hybrid + Reranker

**Конфигурация:**
```bash
RETRIEVAL_MODE=hybrid_reranker
SEMANTIC_RETRIEVER_K=10
BM25_RETRIEVER_K=10
ENSEMBLE_SEMANTIC_WEIGHT=0.5
ENSEMBLE_BM25_WEIGHT=0.5
RERANKER_TOP_K=3
CROSS_ENCODER_MODEL=cross-encoder/mmarco-mMiniLMv2-L12-H384-v1

# LLM
LLM_PROVIDER=ollama
OLLAMA_MODEL=llama3.1:8b
OLLAMA_MODEL_QUERY_TRANSFORM=llama3.1:8b

# Embeddings
EMBEDDING_PROVIDER=huggingface
HUGGINGFACE_EMBEDDING_MODEL=intfloat/multilingual-e5-base
HUGGINGFACE_DEVICE=cpu
```

**Описание:**
- Hybrid retrieval получает топ-10+10 документов
- Cross-encoder переранжирует документы по релевантности
- Возвращаются топ-3 наиболее релевантных документа
- Максимальная точность, но медленнее

## 📈 Сравнительный анализ

### Анализ по метрикам

#### 1. Faithfulness (Обоснованность)
**Интерпретация:** Насколько ответ основан только на retrieved документах, без галлюцинаций.

**Сравнение:**
- Semantic: **0.819** - лучший результат, показывает что ответы основаны на документах
- Hybrid: **0.736** - снижение, возможно из-за большего количества документов от BM25
- Hybrid + Reranker: **0.806** - хороший результат, reranker улучшает качество документов

**Вывод:** Hybrid + Reranker показывает лучший баланс, но Semantic имеет самую высокую обоснованность. Reranker помогает фильтровать нерелевантные документы.

---

#### 2. Answer Relevancy (Релевантность ответа)
**Интерпретация:** Насколько ответ релевантен заданному вопросу.

**Сравнение:**
- Semantic: **0.760** - хороший результат
- Hybrid: **0.785** - лучший результат! Комбинация semantic и BM25 улучшает релевантность
- Hybrid + Reranker: **0.655** - снижение, возможно reranker слишком агрессивно фильтрует

**Вывод:** Hybrid режим показывает лучшую релевантность ответов. Reranker может быть слишком строгим и убирать полезные документы.

---

#### 3. Answer Correctness (Правильность ответа)
**Интерпретация:** Насколько ответ соответствует ground truth эталону.

**Сравнение:**
- Semantic: **0.655** - средний результат
- Hybrid: **0.649** - практически идентичен Semantic
- Hybrid + Reranker: **0.626** - небольшое снижение

**Вывод:** Все режимы показывают схожие результаты. Правильность ответов зависит больше от качества LLM, чем от режима retrieval.

---

#### 4. Answer Similarity (Похожесть на эталон)
**Интерпретация:** Семантическая похожесть ответа на эталонный ответ.

**Сравнение:**
- Semantic: **0.892** - хороший результат
- Hybrid: **0.929** - улучшение! Hybrid находит более релевантные документы
- Hybrid + Reranker: **0.936** - лучший результат! Reranker улучшает качество документов

**Вывод:** Hybrid + Reranker показывает лучшую семантическую похожесть. Reranker эффективно отбирает наиболее релевантные документы.

---

#### 5. Context Recall (Полнота контекста)
**Интерпретация:** Насколько retrieved документы содержат всю необходимую информацию для правильного ответа.

**Сравнение:**
- Semantic: **1.000** - идеальный результат! Все необходимые документы находятся
- Hybrid: **1.000** - идеальный результат! Комбинация подходов не снижает полноту
- Hybrid + Reranker: **0.933** - небольшое снижение, но все еще отличный результат. Reranker может убирать некоторые релевантные документы при фильтрации

**Вывод:** Semantic и Hybrid показывают идеальную полноту. Reranker немного снижает полноту, но улучшает точность.

---

#### 6. Context Precision (Точность поиска)
**Интерпретация:** Насколько retrieved документы релевантны вопросу.

**Сравнение:**
- Semantic: **0.000** - критическая проблема! Retriever не находит релевантные документы (результат до исправления)
- Hybrid: **0.208** - значительное улучшение! BM25 помогает находить релевантные документы по точным терминам
- Hybrid + Reranker: **0.417** - лучший результат! Reranker эффективно фильтрует и ранжирует документы

**Вывод:** Hybrid + Reranker показывает лучшую точность поиска. Reranker критически важен для улучшения качества retrieval.

**Примечание:** Semantic эксперимент был проведен до исправления проблемы с Context Precision (отключен query transformation для evaluation). Hybrid и Hybrid + Reranker эксперименты проведены после исправления.

## 📝 Примечания

### Известные проблемы

1. **Context Precision = 0.000 (исправлено):**
   - Проблема: Query transformation искажал запросы для evaluation
   - Решение: Отключен query transformation для evaluation, используется оригинальный вопрос
   - Статус: ✅ Исправлено

2. **Таймауты Ollama:**
   - Проблема: TimeoutError при использовании Ollama для RAGAS
   - Решение: Увеличены таймауты (600s), уменьшено количество воркеров (1)
   - Статус: ✅ Исправлено

3. **JSON парсинг Ollama:**
   - Проблема: OutputParserException из-за дополнительного текста в JSON ответах
   - Решение: Добавлена обертка CleanedChatOllama для автоматической очистки JSON
   - Статус: ✅ Исправлено

### Методология

- **Датасет:** Использован датасет `06-rag-qa-dataset` из LangSmith
- **Метрики:** RAGAS с 6 метриками (Faithfulness, Answer Relevancy, Answer Correctness, Answer Similarity, Context Recall, Context Precision)
- **LLM для RAGAS:** Ollama (`llama3.1:8b`) - тот же, что и для основного RAG
- **Query Transformation:** Отключен для evaluation (используется оригинальный вопрос)
