# Workflow разработки

Правила выполнения работ по [tasklist.md](tasklist.md) для code-ассистента.

## Общие правила

- Работа строго по плану из `tasklist.md`
- Следовать принципам из [vision.md](vision.md) и [conventions.md](conventions.md)
- Одна итерация = один цикл разработки

## Процесс работы над итерацией

### 1. Подготовка

- Выбрать следующую незавершенную итерацию из `tasklist.md`
- Изучить задачи итерации и требования

### 2. Согласование решения

- Предложить план реализации с примерами кода
- Показать ключевые отрезки кода (импорты, функции, структура)
- Дождаться подтверждения от пользователя

### 3. Реализация

- Реализовать согласованное решение
- Следовать принципам KISS, YAGNI
- Код должен быть простым и работающим

### 4. Подтверждение

- Показать результат реализации
- Дождаться подтверждения от пользователя

### 5. Обновление прогресса

- Отметить выполненные задачи в `tasklist.md` (заменить `[ ]` на `[x]`)
- Обновить статус итерации в таблице прогресса

### 6. Коммит

- Сделать коммит в Git с понятным сообщением
- Формат: `feat: [итерация X] описание что сделано`

### 7. Переход к следующей итерации

- Согласовать переход к следующей итерации
- Повторить процесс с шага 1

## Важные моменты

- Не переходить к следующей итерации без подтверждения
- Не пропускать этапы согласования
- Всегда обновлять прогресс после завершения итерации
- Коммитить изменения после каждой итерации
